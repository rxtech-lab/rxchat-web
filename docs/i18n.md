# Internationalization (i18n) Guide

This application uses `next-intl` for internationalization, supporting multiple languages including English, Chinese Simplified, and Chinese Traditional.

## Supported Languages

- **English (en)** - Default language
- **Chinese Simplified (zh-CN)** - 简体中文
- **Chinese Traditional (zh-TW)** - 繁體中文

## Architecture

### Directory Structure

```
├── app/
│   ├── layout.tsx                 # Root layout with locale routing
│   └── [locale]/                  # Locale-specific routes
│       ├── layout.tsx             # Locale layout with NextIntlClientProvider
│       ├── (auth)/                # Authentication pages
│       └── (chat)/                # Chat pages
├── lib/
│   └── i18n/
│       ├── config.ts              # Locale configuration
│       ├── request.ts             # next-intl request configuration
│       └── routing.ts             # Routing configuration and navigation helpers
├── locales/
│   ├── en/
│   │   └── common.json            # English translations
│   ├── zh-CN/
│   │   └── common.json            # Chinese Simplified translations
│   └── zh-TW/
│       └── common.json            # Chinese Traditional translations
└── components/
    └── language-selector.tsx      # Language selector component
```

### Middleware

The middleware in `middleware.ts` handles:
1. Locale detection and routing
2. Authentication checks with locale-aware redirects
3. API route exceptions

### URL Structure

All pages are prefixed with the locale:
- English: `https://example.com/en/...`
- Chinese Simplified: `https://example.com/zh-CN/...`
- Chinese Traditional: `https://example.com/zh-TW/...`

## Usage

### Using Translations in Components

#### Client Components

```tsx
'use client';

import { useTranslations } from 'next-intl';

export function MyComponent() {
  const t = useTranslations('namespace');
  
  return <div>{t('key')}</div>;
}
```

#### Server Components

```tsx
import { getTranslations } from 'next-intl/server';

export default async function MyPage() {
  const t = await getTranslations('namespace');
  
  return <div>{t('key')}</div>;
}
```

### Using Navigation Helpers

Always use the navigation helpers from `@/lib/i18n/routing` instead of Next.js native ones:

```tsx
import { Link, redirect, useRouter, usePathname } from '@/lib/i18n/routing';

// Link component
<Link href="/profile">Profile</Link>

// Router
const router = useRouter();
router.push('/profile');

// Pathname
const pathname = usePathname(); // Returns path without locale prefix
```

### Language Selector

The `LanguageSelector` component is integrated into the sidebar user navigation menu. It allows users to switch between languages dynamically.

## Adding New Languages

1. **Add locale to configuration** (`lib/i18n/config.ts`):
   ```ts
   export const locales = ['en', 'zh-CN', 'zh-TW', 'fr'] as const;
   export const localeNames: Record<Locale, string> = {
     en: 'English',
     'zh-CN': '简体中文',
     'zh-TW': '繁體中文',
     fr: 'Français',
   };
   ```

2. **Create translation file** (`locales/fr/common.json`):
   ```json
   {
     "greeting": {
       "hello": "Bonjour!",
       "help": "Comment puis-je vous aider aujourd'hui?"
     }
   }
   ```

3. **Test the translations**:
   - Update `locales/locales.spec.ts` to include the new locale
   - Run tests: `pnpm test:unit locales/locales.spec.ts`

## Adding New Translation Keys

1. Add the key to all locale files (`locales/*/common.json`)
2. Ensure the structure is consistent across all locales
3. Run tests to verify consistency

Example:
```json
{
  "newFeature": {
    "title": "New Feature Title",
    "description": "Feature description"
  }
}
```

## Testing

Run i18n tests:
```bash
pnpm test:unit lib/i18n/config.spec.ts locales/locales.spec.ts
```

## Best Practices

1. **Keep translations consistent**: All locale files should have the same structure and keys
2. **Use semantic keys**: Use descriptive key names like `auth.signIn` instead of generic names
3. **Test thoroughly**: Always test with multiple locales to ensure proper functionality
4. **Namespace wisely**: Group related translations under meaningful namespaces
5. **Handle pluralization**: Use next-intl's plural support for count-based translations
6. **Consider context**: Some translations may need different variants for different contexts

## Troubleshooting

### Translations not showing

1. Check that the translation key exists in all locale files
2. Verify the namespace matches between component and translation file
3. Ensure the locale parameter is properly passed in the URL
4. Check browser console for any errors

### Locale routing not working

1. Verify middleware configuration in `middleware.ts`
2. Check that `next.config.ts` includes the next-intl plugin
3. Ensure the `[locale]` directory structure is correct

### Adding translations causes build errors

1. Ensure JSON files are valid
2. Check that all locales have the same structure
3. Run linting: `pnpm lint`
4. Run tests: `pnpm test:unit`
